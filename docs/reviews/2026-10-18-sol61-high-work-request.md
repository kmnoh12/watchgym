## 3. 안정성·용량 개선

Astra 원문을 맹신하지 말고 현재 코드 근거를 확인하면서 다음의 작은 변경을 진행한다.

1. **업데이트 방어 보류**: 최신 사용자 판단에 따라 복잡한 OTA/운동 상호 잠금은 구현하지 않는다. 기존 수동 업데이트 흐름을 그대로 유지한다.
2. **워치 저장 실패 경계**: 청크 파일 쓰기와 상태 체크포인트 사이의 실패를 성공으로 반환하지 않도록 하고, 실패 시 원본과 식별자를 보존하며 재시도/복구할 수 있게 한다. 실패한 저장·명령을 적용 성공으로 ACK하지 마라. 센서/타이머/서비스 시작에서 실제로 예외가 새는 경로를 좁게 감사하고 보강한다. `check/require/!!`를 일괄 삭제하거나 예외를 전부 삼키며 계속 돌게 하지 않는다. 센서 검출 알고리즘은 바꾸지 않는다.
3. **워치 종료 원인 관측**: 폰의 기존 `LocalExitDiagnostics`와 호환되는 수준의 작고 제한된 로컬 진단을 워치에 추가한다. 기존 예외 처리기를 적절히 연결하고 로그 크기를 제한한다. 원격 전송·외부 수집 서비스는 추가하지 않는다. 크래시 후 복구와 운동 도중 실제 끊김을 구분할 수 있게 하고 실제로 측정하지 못한 구간을 지어내지 않는다.
4. **ABI/앱 크기는 별도 변경**: 기존 APK 구성과 현재 지원 기기를 읽기 전용으로 확인한다. 물리 기기의 지원 ABI를 확인할 수 있고 현재 개인 배포 범위를 안전하게 보존할 수 있을 때만 폰 OTA 빌드에 좁은 ABI 최적화를 적용한다. 디버그/에뮬레이터 지원을 유지하고 범용 지원 기기를 근거 없이 제거하지 마라. 확인할 수 없다면 무리하게 제한하지 말고 구체적으로 남은 확인을 문서화한다. 새 전체 빌드/릴리스를 크기 재측정 명목으로 실행하지 마라.

보존할 기존 결정: 최근 앱 스와이프·명시적 강제 종료의 폐기는 사용자 의도에 따른 정책이다. 이것을 자동 저장/복구로 되돌리지 않는다. 명시적 저장/폐기 선택, closed-session 차단, 이미 구현된 journal·outbox·ACK·중복 방지 계약과 기록 형식을 보존한다.

카메라 별도 프로세스, 워치 UI/서비스 전체 분리, 전면 DB 전환, 큰 파일 일괄 분할, 검출기 제거는 하지 않는다. 실제 무고장/Watch8 정확도를 보장하지 마라.
