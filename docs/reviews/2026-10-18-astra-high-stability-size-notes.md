## 실행 확인

Codex2의 실제 계정 한도를 app-server `account/rateLimits/read`로 조회했다. 조회 시 잔여량은 5시간 95%, 주간 49%로, 주 세션의 74%/26%보다 여유가 있었다. 리셋권은 사용하지 않았다.

Codex2 CLI에 `gpt-6-astra`, `model_reasoning_effort="high"`, 읽기 전용 sandbox를 지정했다. 실제 세션 기록에서도 모델 `gpt-6-astra`와 effort `high`를 확인했다. 자문 세션 ID는 `01a14ae5-3d2f-7111-88fb-dc76b2c2bb67`이다. 원문은 CLI의 최종 응답을 그대로 저장했다.

검토자는 소스·기존 APK·공식 문서를 읽었고 코드 변경·새 테스트·빌드·설치·배포를 하지 않았다. 이 메모와 요청 문서, 원문, 플랜의 자문 링크만 주 에이전트가 저장했다.

## 실제 후속 결정을 위한 요점

1. 운동 중 설치와 새 운동 시작이 겹치지 않도록 공통 경계에서 차단할 것을 우선 제안했다. 메뉴 버튼만 막아서는 권한 화면 복귀·워치 지연 요청·타임아웃 경로를 놓칠 수 있다. 실제 운동 중 앱 교체는 이번에 재현하지 않았다.
2. 워치 원본 청크 기록과 체크포인트 저장 사이의 실패를 구분하고, 저장 실패를 성공 ACK나 정상 전환으로 숨기지 말자는 제안이다. `WearWorkoutService.kt`의 청크 저장 후 `persistRuntime()` 반환 무시 경로는 주 에이전트도 소스에서 확인했다. 현장 유실을 관측했다는 뜻은 아니다.
3. 워치 종료 원인과 세션별 복구 지표부터 추가하자고 제안했다. 복구 성공과 사용자가 운동 중 끊김을 경험하지 않았다는 것은 별도로 집계해야 한다.
4. ABI 축소는 안정성 개편과 분리할 것을 제안했다. 기존 폰 OTA APK에서 arm64 외 라이브러리는 33.90MiB였고, 이 항목만 제거한 산술 추정 크기는 약 23.90MiB다. 새 빌드 실측값이 아니며 실제 지원 기기 ABI를 먼저 확인해야 한다.
5. 카메라 프로세스 분리, 서비스/UI 전체 분리, 전면 DB 이전과 대규모 리팩터링은 실제 장애 근거가 생길 때까지 보류하자는 권고다.

## 기존 사용자 결정과 구분할 제안

보고서는 최근 앱 스와이프를 기록 폐기와 분리하자고 권고한다. 그러나 [하드 종료 폐기 정책](../DISCARD_ON_STOP_20261017.md)은 최근 앱 닫기와 명시적 강제 종료의 폐기를 의도된 동작으로 기록한다. 이 문서는 이전의 "최근 앱 닫기도 완료 세트 보존" 정책을 대체한다고 명시한다. 현재 `PhoneWorkoutService.onTaskRemoved()`와 `WorkoutTerminationTest`도 그 정책을 구현·검사한다.

따라서 이 항목은 확인된 구현 결함을 바로 고치는 작업이 아니라, 기존 제품 결정을 바꾸자는 자문이다. 사용자 결정 없이 저장 정책을 되돌리지 않는다. 원문은 독립 자문이므로 수정하지 않았다.
