# 전체 운동의 측정 엔진·시작 자세·반복·수동 처리 명세

2026-10-13 · 기획 부록 1.0 · **구현/정확도 검증 결과가 아닌 설계**

기준은 현재 소스 `WorkoutData.catalog`의 기본 43종이다. 라이브러리 화면에서 접힌 변형도
모두 포함한다. 폰에 사용자가 추가한 커스텀 운동 목록은 이 작업에서 직접 확인하지 못했다.
커스텀 운동은 마지막의 등록 규칙으로 처리한다. 아래 명시적인 운동별 선택은 우리 설계이며,
논문이 이 43개를 동일한 엔진으로 묶어 검증했다는 주장은 아니다.

**기본 측정 엔진은 T(이동 왕복), A(원호/방향 왕복), R(회전 왕복), M(수동)로 공유한다.**
T/A/R은 입력 신호·필터·주기 상태기계·유사도 계산 도구를 공유하고,
운동 레시피는 시작 끝점·힘쓰는 방향·몸통 기준·관측 관절을 설정한다.
기구 하나마다 알고리즘 클래스를 복제하지 않는다. T는 가속도에서 반복 신호를 찾는 엔진이며
센서를 두 번 적분해 정확한 위치를 얻었다고 전제하지 않는다.

`W 후보`는 워치 자동 측정의 **검증 대상**이다. 아직 정확도가 보장되거나 활성화됐다는 뜻이 아니다.
`M 수동`은 정상 수행의 손목 관측 한계에 따른 이번 제품의 기본 정책이다.
푸시업·레그프레스의 모든 가능한 센싱 방법이 물리적으로 불가능하다는 뜻은 아니다.
카메라가 켜져 있고 필요한 관절이 보이는 때의 측정은 별도 능력으로 표시한다.

## G01 · 랫풀다운 · 공통 엔진 T

시작·1회: **팔이 위로 뻗은 시작 A → 손을 몸통 쪽으로 당긴 B → 팔을 다시 뻗은 A**

워치: 당김이 힘쓰는 구간, 되돌림이 반대 구간. 손목의 수직/사선 가속도와 팔꿈치 굽힘을 참고한다.

카메라: 팔꿈치 굽힘, 손목-몸통 경로, 몸통 기울기 변화. 턱 위치/견갑 수축은 손목으로 판단하지 않는다.

| 운동 ID | 앱의 운동명 | 기구 | 계획 모드 | 기구/자세 조건과 설명 |
|---|---|---|---|---|
| `lat_pull_down` | 랫 풀 다운 | 머신 | W 후보 | 기준 양손 동작. 상단 팔 뻗음과 당김 끝점을 확인한다. |
| `wide_lat_pull_down` | 와이드 그립 랫 풀 다운 | 머신 | W 후보 | 와이드 그립은 시작 팔 벌림과 손목 방향 조건만 달리한다. |
| `close_lat_pull_down` | 내로우 그립 랫 풀 다운 | 머신 | W 후보 | 내로우 그립은 손 간격·중립 그립을 기록하며 같은 주기를 쓴다. |
| `reverse_lat_pull_down` | 언더 그립 랫 풀 다운 | 머신 | W 후보 | 언더 그립은 전완 방향 차이를 기록하고 그립 회전을 반복으로 오인하지 않는다. |
| `one_arm_lat_pull_down` | 원 암 랫 풀 다운 | 케이블 | W 후보 | 워치 착용 팔의 반복만 센다. 좌우를 합치지 않으며 보정 측면을 고정한다. |

## G04 · 가슴 프레스 · 공통 엔진 T

시작·1회: **선택한 시작 끝점 A → 반대 끝점 B → A 복귀**

워치: 벤치·인클라인은 같은 내림/밀기 주기를 사용한다. 구현은 손목 회전이 아니라 손의 세로 이동(중력 투영·이동 왕복)을 세는 `TRANSLATION_PRESS_RETURN`이다. 머신은 자연 시작 끝점을 설정하며 좌표축만 보정한다. 랙 이동은 반복에서 제외한다.

카메라: 팔꿈치 굽힘/폄, 손목-어깨 경로, 보이는 좌우 차이. 벤치각/그립 조건을 유지하고 무조건 수직 경로를 요구하지 않는다.

| `rope_extension` | 케이블 로프 트라이셉 익스텐션 | 케이블 | W 후보 | 앱의 패턴은 푸시다운. 로프 벌리기는 끝점 조건이며 추가 반복으로 세지 않는다. |
| `rope_overhead_extension` | 케이블 로프 오버헤드 트라이셉 익스텐션 | 케이블 | W 후보 | 오버헤드+로프 그립 조건. 케이블 오버헤드와 같은 주기를 쓴다. |
| `dumbbell_triceps_extension` | 덤벨 트라이셉스 익스텐션 | 덤벨 | W 후보 | 앱 이름만으로 오버헤드/킥백을 확정하지 않는다. 보정에서 변형을 선택하고 같은 폄 엔진에 매핑한다. |
| `ez_lying_extension` | 이지바 라잉 트라이셉스 익스텐션 | 바벨 | W 후보 | 누운 위팔 기준, 팔꿈치 폄/복귀. 현재 PRESS_RETURN 분류는 공통 삼두 레시피로 재정리할 대상이다. |

## G10 · 외회전 · 공통 엔진 R

시작·1회: **팔꿈치를 굽혀 기준 위치에 둔 A → 손을 바깥으로 돌린 B → A 복귀**

워치: 손목 관측 회전의 왕복을 추적한다. 그립 비틀기와 어깨 동작이 혼동되므로 개인 확인 구간이 필요하다.

카메라: 팔꿈치 이동과 전완 방향 변화를 본다. 한 카메라만으로 정확한 상완 내/외회전각·근육 활성은 판정하지 않는다.

| 운동 ID | 앱의 운동명 | 기구 | 계획 모드 | 기구/자세 조건과 설명 |
|---|---|---|---|---|
| `external_rotation` | 케이블 익스터널 로테이션 | 케이블 | W 후보 | 팔꿈치 위치가 유지되는 기준 동작 확인. 손목 방향 신호만으로 팔꿈치 고정/정확한 어깨 회전각을 판정하지 않는다. |

## G11 · 손목 관측 부족·수동 · 공통 엔진 M

시작·1회: **시작 버튼 → 수행 횟수 입력 → 세트 완료**

워치: 손목 움직임이 운동 반복을 대표하지 않는 정상 수행에서는 자동 반복/템포를 만들지 않는다.

카메라를 켜면 별도 관측 가능성을 검사할 수 있으나 카메라 결과를 워치 자동 능력으로 승격하지 않는다.

| 운동 ID | 앱의 운동명 | 기구 | 계획 모드 | 기구/자세 조건과 설명 |
|---|---|---|---|---|
| `pull_up` | 풀업 | 맨몸 | M 수동 | 봉을 잡은 손목은 몸통 상승을 직접 대표하지 않는다. 기본 워치 수동, 전신 카메라 관측은 별도. |
| `assisted_pull_up` | 어시스티드 머신 풀업 | 머신 | M 수동 | 머신 보조량이 달라도 손목 고정 문제는 남는다. 워치 수동 정책을 공유한다. |
| `leg_press` | 머신 레그 프레스 | 머신 | M 수동 | 정상 손잡이 파지에서 손목은 다리 반복을 대표하지 않는다. 손을 무릎에 얹게 하여 자동화하지 않는다. |
| `seated_leg_curl` | 시티드 레그 컬 | 머신 | M 수동 | 손잡이 잡은 손목으로 무릎 굽힘을 알 수 없다. 정상 수행은 수동. |

| `hip_adduction` | 힙 어덕션 | 머신 | M 수동 | 손목으로 다리 모음을 알 수 없다. 어브덕션과 수동 입력 경로는 공유한다. |

## 스쿼트 시작과 자세·속도의 구체적 계약

선택 운동이 스쿼트이고 세션이 시작 준비 상태일 때, 카메라에서 전신 관절이 보이며
선 자세가 안정되면 READY가 된다. 실제 내려가기 시작할 때 첫 반복과 운동 시간을 시작한다.
앱에 들어오거나 사람이 서 있다는 이유만으로 운동 기록을 시작하지 않는다.

READY → 내려감 → 하단 전환 → 올라감 → 시작 선 자세 복귀 = 1회.
의도한 범위에 못 미친 부분 동작은 별도 표시하고 준비 동작·손 정리·걷기를 제외한다.
내림/하단 정지/올림/상단 정지 시간은 관측 경계로 분리한다.

스쿼트와 랫풀은 T의 반복 추출 도구를 공유할 수 있다. 그러나 스쿼트는 첫 내려감이
주로 내리는 구간이고 랫풀의 첫 당김은 힘쓰는 구간이다. `phaseMeaning`을 운동 레시피에 둔다.
카메라는 스쿼트의 골반/무릎/고관절과 랫풀의 팔꿈치/손목/몸통을 각각 본다.
스쿼트를 랫풀의 팔 자세 규칙으로 판정하지 않는다.

워치가 안정돼 있다는 사실은 사람이 서 있다는 증거가 아니다. 손목만으로 선 자세를 인식했다거나
스쿼트 깊이/무릎 상태를 확인했다고 표현하지 않는다. 워치 조건부 후보는 촬영에서 확인한
개인 움직임 신호와 실제 1회 경계가 대응하는 경우에만 시험한다.

## 3D 궤적·수직성·흔들림을 평가하는 방법

회전 방향 3D, IMU 적분 이동 궤적, 카메라 관절 추정은 서로 다른 자료다.
카메라가 없는 일반 운동에서 그럴듯한 가상 3D 선을 실제 손목 위치로 취급하지 않는다.

촬영 중에는 고정 카메라의 화면 좌표로 신체 이동을 보고 시작 때의 신체 길이로 정규화한다.
MediaPipe world 좌표는 골반 중심이 원점이므로 매 프레임 골반 world y를 읽어
스쿼트 상하 이동 높이라고 할 수 없다. world 좌표는 관절의 상대 각도/관계에 사용하고,
전신 이동은 이미지 공간과 카메라 기준을 따로 유지한다.

제공할 수 있는 값은 다음과 같다.

- 시작 골반 중심/지지 기준 대비 보이는 좌우 이동, 신체 길이로 정규화한 높이 변화.
- 측면 몸통 기울기 변화, 무릎·고관절 각도 추정의 범위, 유효 관측의 반복 시간.
- 같은 조건의 확인된 기준 경로 대비 반복 위상별 편차.
- 목표 경로가 수직이라고 명시된 조건에 한해 수직축 대비 횡방향 편차. 좌우/앞뒤를 관측 가능한 평면별로 구분.

‘수직에서 벗어난 정도’를 무조건 잘못된 자세 점수로 바꾸지 않는다.
벤치 경로와 로우의 기계 원호에는 정상적인 수평/곡선 성분이 있고,
스쿼트도 손목·골반·바벨·무게중심이 동일한 궤적을 갖는 것이 아니다.
보이는 특정 지점의 편차를 설명한다. 한 시점 카메라의 보이지 않는 깊이 변화나
압력중심/발바닥 하중을 측정했다고 말하지 않는다.

## 수동 입력의 구현·검증 계약

워치/폰 어느 쪽에서도 `세트 시작 → 횟수 입력/수정 → 세트 완료 → 휴식`이 가능해야 한다.
수동 대상은 자동 횟수 0회 대신 `수동 입력`을 표시하고 목표 도달 자동 종료를 사용하지 않는다.
워치의 횟수 입력은 운동 중 매 반복 터치를 요구하지 않는다. 세트 후 숫자 ±/회전 입력과 완료를 제공한다.
폰에서도 같은 값을 수정할 수 있다. 목표 횟수를 실제 수행 횟수로 조용히 복사하지 않는다.

폰이 기록의 기준 상태를 소유한다. 워치 명령에는 세션/운동/세트/시도 ID와 중복 방지 ID를 넣고,
영속 명령 큐·적용 ACK로 재전송한다. 완료 뒤 늦게 도착한 이전 시도의 명령은 다음 세트에 적용하지 않는다.
휴식 시작은 한 번만 처리한다. 완료 후 수정은 횟수/기록을 갱신하고 휴식을 다시 시작하지 않는다.
동시 수정은 revision 충돌을 표시하거나 명시적인 사용자 선택으로 해결하며 자동 추정이 수동값을 덮지 않는다.

필수 검증 사례:

1. 레그프레스에서 워치가 정지해도 수동 12회가 양쪽에 같은 setId의 MANUAL 기록으로 남음.
2. 푸시업 수동 입력 중 센서 진동/움직임이 생겨도 자동 횟수가 수동값을 바꾸지 않음.
3. 워치 오프라인 완료 → 폰 연결 복구 후 한 번만 반영, 같은 명령 재전송은 중복 완료/휴식 없음.
4. 폰에서 12→10 수정, 늦은 센서 결과와 오래된 워치 명령이 10을 덮지 않음.
5. 프로세스 재시작/화면 꺼짐 뒤 미전송 명령·완료 기록 복구, 다음 세트와 섞이지 않음.
6. 0회와 미입력을 구분하고, 일반/웜업/드랍 등 세트 종류·중량은 유지.

현재 소스 확인: 폰에는 세트 수행 횟수/수동 출처 처리 경로가 있다. 워치 메인 화면에는
수동 횟수 편집·세트 완료 UI가 아직 없다. 따라서 양 기기 수동 흐름은 미완료이며 실기 검증도 수행하지 않았다.

## 커스텀 운동과 설명 가능성의 완료 기준

커스텀 운동을 이름 문자열만으로 자동 측정으로 승격하지 않는다.
공통 동작 그룹·시작 끝점·착용 팔·지지/기구 조건을 선택하고 확인 자료를 연결한다.
미설정/미검증은 수동이 기본이다. 기존 커스텀 ID와 기록은 유지한다.

각 운동의 상세 설명에는 다음 여섯 가지가 있어야 한다.
`어떤 엔진을 공유하는지 / 어떤 자세에서 준비되는지 / 무엇을 1회로 세는지 /
올림·내림의 의미 / 자세·속도에서 실제 관측하는 것 / 수동 전환 조건`.

운동 라이브러리의 접힌 대표 행과 실제 운동 변형 ID를 혼동하지 않게 한다.
카탈로그 ID 전부에 명세가 연결되고, 신규 운동이 빠졌으면 검사에서 드러나게 한다.
실행 결과에는 사용한 그룹·프로필·시각 경계·제외 이유를 남겨 설명 화면으로 조회한다.
