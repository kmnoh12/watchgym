# 2026-10-28 현장 보고 기반 로컬 수정

## 검증 범위

현재 미커밋 작업본을 보존하면서 수정했다. 아래 변경은 현재 소스의 선택된 단위/서비스/Activity 상태 검사와 컴파일까지 검증했다. APK 조립·배포·설치·실기기 센서 정확도 검증은 수행하지 않았다. 전체 테스트/빌드/린트/스크린샷 스위트는 실행하지 않았다.

## 이번 수정

- `MainActivity.showSetMenu`: 복제/삭제 콜백을 Compose 람다 밖에서 만들도록 변경. 기존 컴파일러 내부 오류(`No mapping for symbol`, MainActivity 수신자 캡처)가 없어지고 폰 컴파일 성공.
- Wear/phone 휴식 일시정지: 만료 경계에서 휴식 잔여 0과 측정 중 일시정지가 같은 상태로 해석되지 않도록 최소 양수 잔여값을 보존한다. 타이머가 이미 0초 처리를 끝낸 뒤 눌러도 일시정지 요청을 보낸다. 폰이 동일한 다음 시도로 먼저 이동했다면 휴식 일시정지/재개 의도를 그 시도의 일시정지/재개로 적용한다. 다른 세션·시도·오래된 순서는 계속 거부한다.
- Wear `applySync(PAUSED)`: 로컬의 경계 휴식과 폰의 다음 측정 일시정지가 만날 때 다음 시도를 초기화하여 이전 횟수와 휴식 표시가 남지 않게 한다.
- `WorkoutSessionReducer.completeSet`: 포화된 과거 위치가 아닌 워치 명령에 쓰는 `nextPendingSet`과 완료 대상을 비교한다. 마지막 완료 세트 뒤 새 세트를 추가하고 그 새 시도를 완료하면 `out_of_order_set`으로 거절되던 경우를 재현 후 수정했다. 임의의 미래 세트 완료는 계속 거절한다. 실제 완료 대상의 exerciseIndex도 반영한다.
- `PhoneSessionController.editPlan`: 화면 스냅샷을 통째로 저장하지 않고 최신 저장 상태에 명시적 편집 의도만 재적용한다. 운동/세트는 고유번호로 다시 찾으므로 백그라운드 완료나 순서 변경 뒤에도 기록과 휴식 마감을 보존한다. 삭제된 대상·다른 세션·안전하게 위치를 복원할 수 없는 Undo는 거부한다. 읽기 이후의 동시 쓰기는 기존 저장 버전 검사가 보호한다.
- 운동 순서 변경: 변경 시작 전 롤백 상태를 보관하고, 종료 시 저장과 워치 재동기화를 수행한다. 실패 시 성공 안내를 하지 않는다. 저장 거절 후에는 롤백에 더해 최신 저장 상태를 화면에 반영한다.
- 스트레이트바 푸시다운(`cable_pushdown`): 사용자 현장 보고에 따라 새 시도의 기본 인식을 로프 푸시다운과 같은 FLEXION_EXTENSION 손목 복귀 방식으로 맞췄다. 과거 translation/press 프로필을 저장한 기록과 진행 중 시도는 당시 프로필로 복원한다. 리버스그립·원암 푸시다운의 translation 방식은 유지한다. 동일한 합성 왕복 입력에서 로프/스트레이트바의 10회 경계가 일치하는 것을 확인했다. 이는 실기기 정확도 검증이 아니다.

## 남은 실측 확인

- 설치된 폰/워치 APK와 현재 작업본의 일치 여부는 기기 연결 후 확인해야 한다.
- 정지 잡음 보정과 목표 정확히 도달 시 1.5초 종료는 이미 로컬에 있었다. 재구현하지 않았다.
- 풀오버/머신 프레스의 내려놓기 +1, 머신 플라이의 빠른 템포/제한 가동범위 누락은 해당 현장 캡처 없이 원인을 확정하지 않았다. 임계값을 임의로 변경하지 않았다.
- 스트레이트바 기본 방식 변경은 사용자가 보고한 유리한 방식과 정렬한 것이다. 손목 각도 변화가 거의 없는 순수 이동 신호는 이전 translation 방식과 다르게 처리되므로 실제 그립/템포에서 확인해야 한다.
