# 워치짐 운동 화면·세트 편집·반복 카운트 검토 (2026-10-27)

## 범위와 검증 수준

중단된 딥시크 작업을 현재 작업트리와 대조해 마무리한 소스 검토 기록이다. 병행 세션의 미커밋 변경을 포함한 현재 파일을 기준으로 한다. 기존 보고서의 구현 설명 중 현재 코드와 다른 부분은 아래 내용으로 정정했다.

**도달한 검증 수준은 소스 수정과 정적 확인뿐이다. 컴파일·테스트·화면·기기 검증은 하지 않았다.** 사용자 지시에 따라 이번 마무리에서는 Gradle 실행, JDK/캐시/경로 우회, 설치·다운로드, APK 빌드·배포·설치, commit/push를 하지 않았다. 다른 세션의 변경을 되돌리지 않았다. 이미지·Blender·뷰어·OneDrive·삭제된 PDF는 변경하지 않았다.

## 1. 사용자 요청과 현재 구현

### 휴식 중 보던 운동 유지

- `MainActivity.commitRunningRoutineEdit`는 `restingPageIndex`를 무조건 지우던 동작 대신 범위 안의 페이지를 유지한다. 활성 운동 커서와 휴식 마감은 별개다.
- 휴식/일시정지 휴식의 스와이프는 `showWorkoutExercise`에서 페이지 선택만 변경한다. `WorkoutScreen`의 `onPageSettled` 콜백은 유지해야 이 분기까지 전달된다. 보고서 초안에 있던 “Compose 콜백 자체 차단”은 현재 구현이 아니며, 차단하면 보던 페이지가 액션 계층에 전달되지 않는다.
- 추가/대체에서 돌아올 때 `returnToBrowsedWorkoutPage`가 휴식이 아직 남아 있으면 기존 페이지를 다시 선택한다. 휴식이 끝났으면 실행 상태를 따른다. 목록 추가는 기존 끝에 붙으므로 기존 인덱스를 유지한다.
- 삭제 시 삭제 지점 뒤의 실행/페이지 인덱스를 보정한다. 보던 운동 자체를 삭제하면 실행 운동으로 돌아간다. 이번 마무리에서 **삭제 취소 시 보던 운동도 복원**하도록 보완했다. 그사이 다른 페이지를 골랐다면 현재 선택을 우선하고, 휴식이 끝났다면 과거 휴식 화면을 되살리지 않는다.
- 서비스 스냅샷으로 운동 객체가 재구성돼도 `applySnapshotToWorkout`는 보던 운동의 세트 ID를 이용해 휴식 페이지를 다시 찾는다. 프로세스 종료 후 재시작할 때의 페이지 선택은 저장하지 않는다. 실행 커서와 휴식 마감은 스냅샷에 저장된다.

### 운동 중 뒤로가기

- 시스템 뒤로가기와 운동 화면의 뒤로가기는 `leaveActiveWorkoutPage`를 통해 실행 중 루틴 개요를 연다. 세션 종료/타이머 리셋 명령은 보내지 않는다.
- 기존 `RoutineDetailScreen`의 세션 제목, 경과시간, 운동별 완료/계획 세트와 총 목표 횟수, 운동 완료·운동 추가를 사용한다. 개요의 뒤로가기는 홈으로 간다.
- 초안에서 추가했다고 설명한 `RunningExerciseSets`/`RunningSetUi`는 **마무리 시작 시 이미 현재 코드에 없었다**. 예시는 운동 목록 개요였으므로 별도의 세트 상세 패널을 다시 추가하지 않았다. `ExerciseScreens.kt`의 다른 세션 변경은 보존했다.

### 다음 세트로 복제

- 시트 문구는 `다음 세트로 복제`다. 활성 세션은 `PhonePlanEdit.DuplicateSet` → `PhoneSessionController.editPlan`을 사용한다. 미리보기는 `duplicateAfter`를 사용한다. 초안의 “활성 세션도 리스트를 직접 수정하고 saveWorkoutChanges 호출” 설명은 현재 구현이 아니다.
- 선택 세트 바로 뒤에 무게·목표·종류·그립·휴식 설정을 복사한다. 완료, 수행 횟수, 출처, RPE와 이전 한쪽 수행 기록은 복제하지 않는다. 새 setId/attemptId를 발급하고 원암 운동은 초기 단계부터 시작한다.
- 측정 중/측정 일시정지 중에는 삽입 지점과 현재 커서가 같아도 커서를 한 칸 밀어 **기존 측정 시도 ID를 유지**한다. 휴식 중 바로 다음 위치에 삽입하면 복제본을 다음 세트로 삼는다. 더 뒤의 커서는 이동한다.
- 운동별 탐색 커서와 선택 세트는 세트 ID로 다시 매핑한다. 저장 성공 후 커밋된 스냅샷으로 UI를 갱신하고 SYNC를 보낸다. 저장 실패 시 후보를 적용하거나 워치 명령을 보내지 않는다.
- `WearWorkoutService.sameSet`은 ID가 있는 경우 setId/attemptId로 비교한다. 동일 시도의 SYNC는 바뀐 세트 번호/설정만 반영하고 실행 중 카운트를 새로 시작하지 않는 경로가 있다. 휴식 SYNC에는 절대 마감과 휴식 버전이 포함된다. 실제 기기 연속성은 미검증이다.

## 2. 이번 마무리에서 보완한 결함

수정 파일: `phone/.../MainActivity.kt`, `phone/.../WorkoutEditSafetyTest.kt`, 이 보고서. 그 외 기존/병행 수정은 유지했다.

1. **운동 이동 저장 거절 시 메모리 상태 누출**: `showWorkoutExercise`가 이전 시도 ID, 실행 위치, 운동별 탐색 정보를 변경한 뒤 저장에 실패할 수 있었다. 이동 전에 기존 편집 롤백을 시작하고, 롤백이 휴식 페이지·스크롤·운동별 커서 맵도 복원하도록 보완했다. 저장에 실패했는데 이전 시도를 취소한 상태만 메모리에 남는 것을 막는다.
2. **운동 삭제 실패와 Undo**: 삭제 전에 롤백을 준비한다. 저장에 실패하면 복원하고 성공용 Undo를 띄우지 않는다. Undo도 저장 거절에 대비해 롤백을 준비하며, 현재 실행 운동을 객체 동일성으로 찾아 인덱스를 복원한다. 삭제한 휴식 페이지를 즉시 취소했을 때 다시 보여 주되 휴식 마감은 되감지 않는다.
3. **대체 운동으로 미완료 한쪽 결과 전이**: 원암 첫쪽 완료/다른쪽 대기 상태는 `completed=false`여도 기록을 갖는다. 운동 대체가 이를 그대로 복사하던 경로에서 새 운동의 초기 unilateral 상태로 바꾸고 수행 횟수·출처·RPE를 비운다. 기존 attemptId 갱신과 분석 제거는 유지한다. 대체 전 롤백을 준비하고 저장 실패 시 성공 안내를 하지 않는다.

4. **백그라운드 완료가 다른 화면을 덮음**: `refreshActiveSession`이 마지막 세트 이후 실행 커서가 끝에 도달하면 현재 화면과 관계없이 완료 판단 화면을 열던 경로를 수정했다. 자동 전환은 운동/휴식 화면에서만 한다. 라이브러리·정보 화면은 유지하고, 실행 중 개요는 현재 스냅샷으로 갱신한다. 세션을 새로 복구할 때도 개요를 운동 페이지로 강제 전환하지 않는다.

의도적으로 변경하지 않은 것: 센서 임계값, 검출기 라우팅, 기존 운동/세트 편집 UI 디자인, 스냅샷 형식, 자산과 배포물.

## 3. 카운트 경로와 근거

### 소스에서 확인한 경로

- `ExerciseMotionCatalog`: 머신 풀다운(핀식/플레이트식/프론트 포함)과 랫풀다운은 `PULL_RETURN`, 머신 시티드 로우(`seated_row`, `machine_row_plate`), 머신 하이 로우(`high_row_machine`), 케이블 시티드 로우(`cable_seated_row`)는 `CYCLE_AXIS_RETURN`이다.
- `WearWorkoutService.configureTracking`은 새 시도에서 `ExerciseTrackingProfiles.resolve`를 사용한다. 복구 중인 시도는 저장된 프로필을 유지할 수 있다. 일반 경로는 센서 → 시작 게이트 → `ProfiledMotionRepDetector` → `recordDetectedRepAt` → `postTargetGuard`/`setEndGate` → 횟수 증가다. 별도 패턴 바인딩이 활성화된 세트는 다른 경로가 가능하므로 실제 세트의 프로필/바인딩 기록이 필요하다.
- `PULL_RETURN`의 현재 일반 로브 경로는 반대 부호 로브를 짝지어 두 번째 로브가 닫힐 때 이벤트를 낸다. 시작이 잘린 첫 로브 구제 코드도 있다. 복구된 구버전 프로필은 동작 차이가 있을 수 있다.
- `CYCLE_AXIS_RETURN`은 `CycleAxisRepDetector`로 위임한다. 20초 창을 0.1초 간격으로 재분석하고 gyro/동적가속 후보의 주성분 축과 피크를 구한다. 피크 확정 대기는 0.3초이며 평활화/피크 창/분석 주기 지연도 있어 사용자 동작 기준으로 정확히 0.3~0.4초라고 보장할 수 없다.
- 로우에는 lateral-raise 전용 `countOnReturn`이 적용되지 않는다. 따라서 피크가 당김 정점인지 복귀인지, 사용자 몸의 어느 시점인지는 소스만으로 확정할 수 없다. 초안의 “카운트 시점은 수축 정점이 아니다”는 과도한 단정이었다.

### 확인된 구조적 위험과 미확인 가설

| 관찰/가설 | 현재 판단 |
|---|---|
| 마지막 손잡이 내려놓기 +1 | CycleAxisRepDetector 주석에 명시된 알려진 위험이다. 사용자가 겪은 세트가 이 경로였는지는 미확인이다. |
| 첫 동작 2회 | 첫 피크부터 전달하며 첫 이벤트 이후 1.2초 이내의 다음 후보를 거르는 규칙이 있다. 더 멀리 떨어진 별도 후보/축 재투영/신호 재선택 등이 원인 후보지만 raw 없이는 어느 것도 확정할 수 없다. 같은 부호 피크의 가설과 당김/복귀 두 로브 가설은 구분해야 한다. |
| 그립별 큰 오차 | 첫 이벤트가 gyro/동적가속 소스와 부호를 잠그지만 **주성분 축 자체를 고정하지는 않는다**. 축은 창마다 다시 계산되고, 마지막 피크 이후 8초가 지나면 잠금도 해제된다. 초안의 “축 고정, 세트 내내 유지”는 틀렸다. 그립별 손목 신호가 다르다는 것은 가설이며 실제 원인은 미확인이다. |
| 느린 수직 당김과 중력 필터 | PULL_RETURN의 COMBINED_MOTION은 gyro + dynamic×0.12를 사용하며 중력 필터 alpha=0.10이다. 느린 병진 성분이 줄어들 가능성은 있지만 원인 입증은 아니다. **하이 로우는 이 로브 경로가 아니므로 이 가설의 동일 대상에 넣지 않는다.** |
| 준비 전 첫 당김으로 첫 반복이 잘림 | 2초 안정 시작 게이트를 통과하기 전 동작은 계수에서 빠질 수 있다. 사용자 시작 시점 로그 없이 이번 증상의 원인으로 단정할 수 없다. |
| 오계수 → 목표 도달 즉시 자동 종료 | **일반 운동에는 해당하지 않는다.** CapturePurpose.WORKOUT.stopAtTarget=false, LEGACY_CALIBRATION만 true다. 일반 운동의 종료는 별도 세트 종료 게이트와 사용자 완료 흐름도 봐야 한다. 초안의 일반적인 조기 종료/데이터 손실 주장은 철회한다. |

### 데이터 확인과 한계

`work/evidence/*/watch.manifest` 5개를 확인했다. exerciseId는 preacher_curl 2개, rope_extension 3개다. 이 5개에는 이번 풀다운/하이로우/시티드 로우 증상을 검증할 대상 캡처가 없다. 이는 저장소/기기/외부 경로 전체에 데이터가 없다는 증명은 아니다. 검출기 주석에는 과거 Watch8 케이블 로우 1세트를 개발에 사용했다는 기록이 있으나, 이번 증상의 라벨 자료와 동일하다는 근거는 없다.

대상 운동의 실측 신호와 수동/영상 라벨을 대조하지 않았으므로 정확도 개선·원인 확정을 주장하지 않는다. 임계값, 첫 쌍 간격, 가족 라우팅을 추정으로 변경하지 않았다.

## 4. 검증 기록

### 이번 마무리

- 현재 소스의 호출·상태·ID·저장 실패·워치 SYNC 경로를 정적으로 추적했다.
- `RunningExerciseSets`, `RunningSetUi`, 이전 문구의 잔여 참조를 검색했다. 해당 추가 패널/이전 문구는 현재 phone 소스에 없다.
- 변경 파일의 `git diff --check`로 공백 오류를 확인했다. 컴파일·동작 검증이 아니다.
- 회귀 검사 3개를 작성했다: 저장 거절 시 운동 이동의 커서/시도/탐색 정보 복원, 휴식 중 운동 삭제 취소 시 페이지/마감 보존, 백그라운드 완료 수신 시 라이브러리 화면 유지. **실행하지 않았다.**
- 기존의 복제 순서/새 ID/기록 미복사, 휴식 페이지, 활성 측정 시도 유지, 단일 세트 삭제/취소 테스트도 소스만 검토했으며 이번 트리에서 통과했다고 주장하지 않는다.

### 이전 딥시크 실패 기록 (이전 보고서에서 인계; 이번에 재실행 안 함)

1. `./gradlew :phone:compileDebugKotlin`: wrapper 없음.
2. 번들 Gradle: Java Runtime 찾기 실패.
3. 프로젝트 JDK 지정: native services/lock 권한 실패.
4. 임시 GRADLE_USER_HOME 등 우회: 한글 경로가 깨져 JDK/소스 경로 오류.
5. ASCII 경로 JDK 복사/툴체인 고정 우회: 경로 오류 지속.

이 실패 원인들을 현재 환경에서 새로 확정한 것은 아니다. 사용자 금지에 따라 Gradle·환경 우회를 반복하지 않았다.

## 5. 남은 검증

컴파일 오류가 없다는 보장, 실행 테스트 통과, 실제 UI 모양/상호작용, 폰↔워치 연속성은 모두 미확인이다. 빌드/테스트 금지가 해제된 정상 환경에서만 변경 클래스의 최소 검사와 기기 확인이 필요하다. 현재 요청에서는 더 실행하지 않는다.

- UI/상태: 휴식·일시정지 휴식 중 다음 운동 보기 → 추가/대체/삭제/Undo, 화면 밖에서 휴식 종료 후 복귀, 뒤로가기 개요.
- 세트: 완료 세트/미완료 세트 복제, 현재 측정 세트 앞 복제, 복제 후 저장 실패, 삭제/취소 후 ID와 다음 세트 및 워치 카운트 유지.
- 대체: 원암 첫쪽 완료/다른쪽 대기에서 운동 대체 후 이전 결과 미전이, 저장 실패 시 원상 복원.
- 실측: Galaxy Watch8 대상 운동별 2세트 이상, 8~12회, 영상·수동 첫/마지막 경계 라벨·watch.kcs/manifest. 머신 풀다운 핀식/플레이트식, 하이로우, 시티드 로우 와이드/뉴트럴/언더, 케이블 시티드 로우를 구분한다. 첫 반복과 마지막 손잡이 놓기를 별도 라벨링하고, 실제 프로필/패턴/시작 게이트 기록도 함께 확인한 뒤 수정 방향을 정한다.
